# Web answer recovery after context compaction

Reproduce with a long local-model conversation near its context limit, enable Internet, and ask a short factual question. Search can return relevant references, but an overflow retry previously replaced the current prompt with a generic instruction to continue from the transcript. A model could then narrate recovery or unsuccessful memory lookups instead of answering from those references.

The scoped Capri compatibility fix retains the current owner request and its supplied references in the internal, non-persisted recovery prompt. Completed actions must not be repeated. Ordinary web questions use a shorter informational prompt and the conversation tool scope; explicit action domains retain their existing verification.

Internet turns also prevent implicit desktop escalation before search begins. They cannot inherit an old computer-task follow-up or consult the desktop intent classifier to reinterpret a factual question. The host rejects generated desktop actions and full-access enablement before native execution, including direct execution callbacks. Ending an existing session and revoking access remain possible. An explicit current computer-mode request remains separate and can still execute its authorized goal.

Explicit private reasoning frames are filtered even when Thinking mode is off, including Gemma 4 native channels. Closing avatar markers are removed at the streaming boundary before display, persistence and speech, without selecting an avatar or enabling microphone continuation.

Validation covers recovery prompt generation, compatibility upgrade and idempotency, source propagation, action-domain preservation, private-channel framing and every split point of closing avatar markers. Routing regression checks include factual questions in six languages, granted and ungranted computer access, failed search, prior incomplete computer tasks, generated desktop tool calls, cleanup and explicit computer requests. No conversation or memory reset is required.
