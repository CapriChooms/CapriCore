# Scientific calculation with an omitted tool target

A real application test asked Capri to calculate `3^4 + 6! - sqrt(949)` using the scientific calculator. Calculator access was enabled, but the model omitted the redundant `app` field from its `application_control` calculation call. The host rejected that call with a target-selection error, and the model incorrectly described the failure as disabled Calculator access.

The calculation action now infers its only supported target, Calculator, when `app` is absent. Normalization occurs before permission checks and operation fingerprinting. An explicit different target is still rejected, app permissions remain required, and opening or focusing an application still requires an explicit target. Calculator windows are not opened for background calculations.

Reproduce through a tool call containing `action: "calculate"`, the expression above and `showWindow: false`, without `app`. With Calculator enabled, the verified result is `770.1941563985013`. With permission disabled, the same request must fail before computation. Retrying the same operation with the explicit Calculator target must reuse its completed receipt.

Focused regressions cover the exact scientific expression, permissions, incoming argument immutability, operation identity, ambiguous actions, explicit invalid targets, and normal calculation modes.

A subsequent real test explicitly requested the Calculator window. This time the model supplied `3**4 + factorial(6) - sqrt(949)`: Python-style power syntax. The numeric parser rejected `**` before any window launch, and repeating the same expression reached the tool-loop limit. Numeric-expression normalization now accepts `**` as the existing `^` power operator before the same bounded parser and AST checks. Exponent limits, forbidden functions, assignments and malformed operators remain rejected. Tests verify the exact expression, right-associative and negative powers, and that a successful calculation precedes the requested window launch.
