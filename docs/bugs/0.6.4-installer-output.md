# Installer component output can lose its final diagnostic

Setup's child-process reader treated each pipe chunk as an independent UTF-8 string, shared one unfinished line between standard output and standard error, and emitted only newline-terminated lines. A split non-ASCII character could become replacement characters. An intervening warning could join an unrelated progress line. A component's final status or failure detail could remain undisplayed if it omitted the trailing newline.

The reader now gives each pipe its own streaming UTF-8 decoder and bounded unfinished line. It flushes remaining text when that pipe closes, accepts carriage-return progress updates, and strips terminal formatting after assembling a line. Failure details retain the existing bounded tail and actual child exit code. Timeout, cancellation and owned-process termination behavior are unchanged; the reader does not retry installation commands.

Seven real-subprocess regressions reproduce the defects against the prior reader and pass with the correction. They cover multilingual bytes split between writes, interleaved pipes, final unterminated status and failure messages, carriage-return progress, split terminal formatting and output-size limits. Existing cancellation and npm download-recovery checks also pass. The fixtures use synthetic child processes and disposable local package servers, without installing Capri or changing user settings.

The existing request-classifier report in issue 78 lacks the Python verification's own failure detail. Better output handling is useful for diagnosing another attempt, but does not establish that the original native verification failure is fixed. The affected installation still needs a fresh Setup report after retrying.
