# Local planner rejects the first computer action

Actual browser, Explorer and Discord requests stopped before their first action. The local inference boundary returned HTTP 500 with the native decoder error `The model produced output that does not match the expected peg-native format`. No mouse or keyboard action had run. A reduced request without screen text produced the identical error, distinguishing this failure from permissions, foreground selection or resource-allocation errors.

The planner now recognizes only this bounded, specific native error and retries the failed inference once using JSON output mode. It remembers the compatible mode for that planner instance. Ordinary server failures, memory errors, malformed responses and cancelled requests do not trigger this fallback. No dispatched desktop action is retried.

Every planner result must pass the complete host-side action schema before use, including external API adapters that request JSON objects rather than enforce a full schema. Checks cover required fields, current targets and evidence, first-action checkpoints, nested fields, types, length/range limits, patterns, enums and rejection of extra fields. Existing permission checks, observation validation, native input preflight and completion verification remain required. Compact output hints reuse targets already present in the observation rather than duplicating their large enum lists in the prompt.

To verify, use an affected local runtime to request a browser task with several steps. The initial native-format failure may cause one additional inference; the compatible response must produce a validated first plan. Subsequent plans use the compatible format directly. A fabricated target, missing application argument, absent first checkpoint plan or invalid completion review must be rejected before input. Stop with Escape to confirm cancellation still prevents the format retry.

Focused regressions cover the exact error, one-time/cached behavior, unrelated failures, cancellation, malformed packets, full schema validation, current target selection and completion reviews. A read-only production probe using real native controls verified the HTTP 500 to HTTP 200 transition and accepted the validated first action without dispatching input; full application execution is checked separately.
