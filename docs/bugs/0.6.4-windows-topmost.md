# Ordinary pinned windows lost their Windows topmost state

## Reproduce

On the affected Windows/Electron 45 runtime, enable Capri's always-on-top preference, then open or restore the home interface or Settings. The saved preference can be enabled while another ordinary application remains above Capri and intercepts input at the same screen position.

An independent native check showed that `GetWindowLongPtr(hwnd, GWL_EXSTYLE) & WS_EX_TOPMOST` was zero. The isolated reproduction created a small offscreen Capri-owned window, with no user input or focus changes. Both the constructor's `alwaysOnTop: true` and `setAlwaysOnTop(true)` at the default/`floating` level failed to set that flag. Explicit `setAlwaysOnTop(true, 'normal')` set it correctly. This distinguishes the failure from a cached label or an unrelated window covering the interface.

## Change

Ordinary home, Settings and restore-chip windows now explicitly apply the tested `normal` level on Windows. Other platforms retain the boolean API. Turning the preference off still uses `false`; computer control still temporarily lowers the interface and restores the latest saved or preview preference on completion, cancellation or indicator failure. Avatar and emergency-control effect layers retain their existing separate levels.

## Verify

Check the actual Windows topmost flag before and after construction/restoration, then verify pointer input reaches Capri in a non-overlapping area of its own interface. Repeat with the preference disabled and during/after computer-control cancellation. The fix must not change a foreign window, steal focus, move the interface, or save a temporary demotion as the user's preference.

Focused regressions cover Windows level selection, unchanged non-Windows calls, enabled/disabled construction, Settings reuse and preference changes, restore-chip reuse, control cancellation and rollback. Native offscreen reproduction independently confirmed the level-specific behavior; it does not establish an upstream implementation cause.
