# Electron runtime download fallback

## Report and cause

A 0.6.3 installation completed npm installation, then received HTTP 504 while
fetching the separate Electron 45.0.0 Windows x64 runtime. It failed before
Ollama and model installation. The captured report identifies the component but
does not establish which gateway generated the 504, or whether a VPN was used.

## Sources and integrity

GitHub remains the primary source. The fallback is the npmmirror URL listed in
`config/installer.json`; npmmirror is a third-party mirror referenced by
[Electron's official installation documentation](https://www.electronjs.org/docs/latest/tutorial/installation).

Both sources must deliver the same 158223852-byte archive with pinned SHA-256
`ae53887a23bb640369c93dbd38c408a2af5c0deb86f2fa76c6c244cb444b7f47`.
The version, size and checksum are never replaced with values from a mirror.
All redirects remain HTTPS and subject to the explicit host allowlist. No
authentication or proxy configuration is copied to a mirror.

Fallback applies to transient network/server failures. Cancellation, pause,
unapproved redirects, TLS certificate failures, invalid byte ranges and
integrity failures must retain their existing fail-closed behavior. Partial
files from different sources are kept separate. Only verified complete files
share the hash-addressed final cache.

## Network verification, 8 November 2026

Remote Globalping probes issued HTTP HEAD requests from five distinct networks,
reusing the same probes for both sources and the mirror's final CDN URL.

| Probe network                 | GitHub initial URL             | Mirror final CDN |
| ----------------------------- | ------------------------------ | ---------------- |
| Rostelecom, Kostroma, AS12389 | First-byte timeout, 15 seconds | 200              |
| Vimpelcom, Samara, AS3216     | First-byte timeout, 15 seconds | 200              |
| ER-Telecom, Penza, AS41754    | First-byte timeout, 15 seconds | 200              |
| Hetzner, Germany, AS24940     | First-byte timeout, 15 seconds | 200              |
| HostPapa, USA, AS36352        | 302 redirect                   | 200              |

Every mirror CDN response advertised the pinned byte size. HEAD requests did
not download the archive. One probe is not a qualification of an entire ISP,
and the German timeout does not establish a specifically Russian restriction.
The GitHub signed CDN target was not included in the remote measurements.

A separate full download from the development connection transferred all
158223852 bytes from the mirror CDN and matched the exact pinned SHA-256. The
archive was not executed. Network/VPN settings were not changed.

## Reproduction and expected behavior

Simulate a 504, reset or first-response timeout on the primary source. Setup
should select the configured mirror and finish only after the original pinned
size/hash checks pass. A changed archive, invalid redirect or invalid range must
still fail. Verify cancellation, pause/resume, separate source partials and
reuse of a previously verified cache.

Already distributed 0.6.3 installers do not acquire this fallback automatically;
use the new installer containing this change.
