# Uninstall progress and recovery

## Symptoms and cause

After the user confirmed component removal, the component-selection dialog closed. PowerShell continued preflight checks and deletion without a progress window, so a large installation could appear to have stopped responding. A completed removal could therefore be mistaken for a failed one.

The separate message about missing uninstall files came from the native launcher checking only the recovery location recorded when the app was installed. A valid copy in the installation could still be present.

## Change

Interactive removal keeps a responsive window open, showing preparation, stopping Capri, removing selected components and final cleanup. A counter reports completed file and cleanup operations without another expensive file-counting pass. The active indicator does not claim a percentage or ETA. Success is displayed only after all selected work finishes; failures remain visible with technical details.

The native launcher resolves a complete verified recovery bundle for the managed installation, with an installed-copy fallback. It rejects incomplete, foreign or linked executable content. Quiet, measurement and plan-only modes retain their noninteractive behavior.

## Verification

Use an expendable installation. Confirm removal and check that progress remains visible and responsive while files are processed. Check application-only removal and removal of all selected components separately, verifying that unchecked data is preserved. Remove only the recovery copy in a fixture and confirm that resolution selects the verified installed bundle. An incomplete or altered bundle must require repair instead of execution.

Never use a real user's installation to test destructive deletion automatically.
