# Public issues reviewed for 1.0.1

## Issue 8 — connection test succeeds, conversation is incomplete

[Report](https://github.com/CapriChooms/CapriCore/issues/8): an external API passed
the connection test but a normal Spanish conversation ended with `RESPONSE
INCOMPLETE`. The report recorded a model-phase failure after about 20 seconds,
below the configured conversation deadlines. The old archive omitted the model
ID, provider details and typed transport error, so it cannot establish the
author's exact upstream failure. High system RAM use or an AMD card does not
establish its cause.

A concrete compatibility failure was reproduced: a provider accepts
`stream: true` but returns an ordinary `application/json` completion. Previously
the connection test used a non-streaming cloud request and passed, while the
proxy forwarded that JSON under an SSE content type. The conversation consumer
received no valid streamed answer.

The proxy now validates and converts a buffered completion to stream events,
preserving choice indexes, function calls and finish reasons. It strips private
reasoning and credentials, enforces byte/cancellation limits and sends the user
request only once. Remote connection tests exercise this same streaming adapter
and reject empty, failed or incomplete streams. Existing bounded local Ollama
and Lemonade compatibility paths remain separate.

Reproduce with a fixture returning a JSON assistant completion despite
`stream: true`; verify visible text/tool calls and the final stream marker.
Repeat with a native stream, truncated stream, malformed response, provider
error, cancellation and a split/escaped credential canary. The native stream
must remain incremental, failed requests must not replay, and diagnostic metadata
must contain only the safe failure classification. The affected user's provider
still needs a retest; this does not claim that every possible cause of the
original incomplete reply has been identified.

## Issue 9 — resource labels stay selected

[Report](https://github.com/CapriChooms/CapriCore/issues/9): dragging or double-clicking
CPU/GPU/RAM/VRAM text selected interface labels and left a grey highlight.
The renderer inherited ordinary document selection, and some secondary settings
surfaces explicitly enabled it.

Interface surfaces now disable ordinary selection. Editable fields retain normal
editing; Capri's answer in the main dialogue and assistant answers in history
remain selectable. Only actual main-answer text receives a pointer hit region;
the surrounding transparent stage remains click-through. Native routing for the
separate desktop bubble is unchanged.

`tools/verify/verify-text-selection.mjs` reproduces the former CPU selection in a
disposable renderer, then uses mouse drags and double-clicks on all four resource
labels, checks graph/ring controls, Settings/Credits, answer selection and Ctrl+A
editing. It uses no owner history, model, microphone or system capture.

## Model IDs and safe diagnostics

The selected model ID now appears in `session.json`, `REPORT.md` and the bounded
`desktop-model.jsonl` technical record. Each startup replaces the last model
record; it does not accumulate conversation data. Only a validated identifier is
retained. Credentials, personal paths, URLs, request text and provider response
bodies remain excluded.

Chat and API failures keep separate stage/code/status counters. These describe
what failed without pretending that a successful small connection probe proves
every tool, image or long-context request will work.
