# Capri Desktop experience implementation plan

Работа ведётся поверх текущей архитектуры Electron. Основной процесс остаётся владельцем разрешений, настроек, устройств и нативных окон. Рендереры отвечают за интерфейс. Новые названия и подсказки на этом этапе оформляются на английском. Существующие переводы сохраняются до отдельного прохода локализации.

## 3. Вложения и мультимодальность

**Пункт 4.** Добавить кнопку, drop zone и карточки вложений в composer. Рендерер передаёт выбранный файл через узкий IPC с привязкой к отправляющему окну, без произвольного чтения путей по запросу модели. На стороне main валидация magic bytes, размеров, количества, времени работы и capability активного профиля. Подготовка файлов выполняется изолированно и отменяется вместе с черновиком. При отказе пользователь видит конкретную причину, введённый текст сохраняется.

- Первый этап поддерживает TXT, Markdown, CSV/JSON и JPEG/PNG/WebP. Текст ограничивается по токенам и передаётся как цитируемое содержимое. Картинки нормализуются и идут через ограниченную ветку vision, с явной индикацией передачи внешнему API.
- Второй этап поддерживает DOCX/ODT как ограниченный ZIP с извлечением текста, PDF как текстовые страницы с выделенным безопасным парсером, GIF как выборку кадров и MP4/WebM как ограниченную по длительности последовательность кадров. Не запускать макросы, скрипты, ссылки и встроенные объекты. Содержимое файлов не может выдавать разрешения инструментам. Для видео использовать кодек из комплектуемого декодера и указывать, когда анализируются кадры, а не аудио.
- Совместимость считать по формату подготовленного содержимого. Для файла, требующего vision, текстовый профиль получает понятный отказ до запроса. При смене модели повторно проверять черновик. Изображения и байты не попадают в журнал или память. Хранить только явную реплику пользователя и ответ, в истории показывать компактную отметку о вложении.
- Тесты включают поддельные расширения, повреждённые контейнеры, oversized payload, ограничение декодирования, отзыв доступа и смену профиля, локальный и внешний vision, отмену и очистку.

Микрофонный тракт во время звонка должен быть непрерывным. Для минимизации задержки передаём PCM короткими буферами через один активный граф, а TTS-ветка добавляется на время ответа. Синтетические тесты проверяют микс, маршрутизацию и отказ. Реальная задержка, выбор устройства в клиенте звонка и акустика требуют тестового звонка. [Документация WASAPI](https://learn.microsoft.com/en-us/windows/win32/coreaudio/wasapi)

## Порядок внедрения

1. Исправления стабильности, существующие переключатели и представление настроек. Фиксируем базовые сценарии и совместимость старых предпочтений.
2. Слои анимации, drag, взаимодействия на рабочем столе и голосовые пресеты. Тестируем на изолированных окнах с синтетическими устройствами и аудио.
3. Вложения с capability gate, затем форматы с декодерами. Отдельно проверяем локальный профиль и внешний API.
4. Wake от Windows playback и виртуальный микшер звонка. Ручное подтверждение для смешанного ввода и отдельное разрешение на трансляцию. Живой тест после изолированного.
5. Прикреплённые позы, схема зон и квалификация каждого набора кадров. Переходы и рот тестируются отдельно и совместно.

## Границы текущего внедрения

- Боковой и потолочный хват используют отдельные рисованные позы с точками контакта на пальцах. Голени качаются отдельными слоями, а рот компонуется поверх стабильной головы. Молния при перетаскивании проходит через окна и мониторы. Слои молнии прозрачны для мыши и закрываются при отпускании кнопки.
- Короткие локальные реплики используют язык загруженного голоса, в том числе при автоматическом выборе. После серии нажатий ответ модели использует текущий язык диалога. Области нажатий проверены на 32 используемых PNG-кадрах и на трёх вариантах хвата. При проверке используется та же геометрия, которой рисуются отражённая поза и движущиеся ноги. В хвате выражение меняется отдельным слоем вокруг глаз.
- Вложенный PDF читается как текст, скан без текстового слоя отклоняется с сообщением. GIF и видео читаются по выборке кадров без звука. При отправке через внешний API обработанное содержимое получает выбранный провайдер.
- Системный захват проверен через реальный Windows loopback, а передача микса и его изоляция проверены через виртуальный Steam Streaming Microphone. Обе проверки используют тестовые звуковые сигналы. Звонок с другим участником и физические мониторы с разным DPI требуют ручной проверки. [Настройка аудиомаршрута](desktop-voice.md)
- Кнопки Boosty, Discord и GitHub используют официальные знаки. Кнопка TikTok оформлена в его палитре с нейтральным значком видео. Для официального логотипа требуется письменное разрешение TikTok. [Правила TikTok](https://developers.tiktok.com/docs/en/getting-started-design-guidelines)
