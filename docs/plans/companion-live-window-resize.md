# Плавное изменение размеров окна Capri

## Причина

Прозрачное окно Capri меняет координаты и размер через `BrowserWindow.setBounds`. При изменении размера за верхнюю или левую грань Windows успевает показать последний кадр по новым координатам до того, как Chromium перерисует содержимое под новый размер. Системный прямоугольник в этот момент верный, а противоположная видимая грань временно смещается. В замере на Windows правая граница смещалась на 5 пикселей и затем возвращалась. Переключение DirectComposition не устранило сбой. [Ограничения прозрачных окон Electron](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles#limitations)

## Изменения

1. Выделить основной интерфейс в прозрачный `WebContentsView` внутри `BaseWindow` на Windows. Оставить существующие preload, ограничения навигации, проверку источника IPC, click-through и настройки графики. Представление получает точный размер видимой области, поэтому существующие CSS, брейкпоинты и раскладка продолжают работать. [Документация Electron по BaseWindow](https://www.electronjs.org/docs/latest/api/base-window)
2. Сохранить начальный прямоугольник и курсор в DIP на всё время жеста. Пределы брать из рабочей области выбранного монитора и минимального размера текущей компоновки. Для изменения размеров закрепить противоположные грани и заранее вычислить область, достаточную для хода выбранных граней. В этой области изменять координаты и размер `WebContentsView` одним вызовом, удерживая положение нативного окна. При смене происхождения координат кратко удерживать последний кадр Capri через `UpdateLayeredWindow`. Снимок берётся только из представления Capri и живёт в памяти до готовности нового кадра. После отпускания сохранить итоговые размеры видимого окна и вернуть нативное окно к этим границам. [Документация Windows по UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)
3. Привязать изменение размеров и перетаскивание за заголовок к `requestAnimationFrame` при движении курсора. На кадр запрашивать только последние координаты курсора, с максимум одним запросом в работе. Последний отсчёт применять при отпускании. Неподвижному окну оставить обычную проверку click-through без цикла отрисовки, вызовов установки размеров и непрерывных IPC. Смена компоновки, потеря фокуса, скрытие и изменение топологии мониторов завершают активный жест.
4. Изолировать прилегающие источники движения. При активном жесте заморозить позиционирование по видимому контуру и остановить изменение размера от облачка. На выходе согласовать его состояние и записать только итоговую геометрию. Во время изменения размеров обновлять компоновку портрета, текста и поля ввода с частотой дисплея. Пересчитывать области попадания мыши после отпускания.

## Проверка

Использовать тесты расчёта всех восьми направлений, минимального размера и мониторов с отрицательными координатами. В Electron проверить реальные отрисованные грани, перемещение за заголовок, работу после отпускания, вертикальную и горизонтальную компоновки, повторный запуск и дробный DPI. Отдельно собрать тестовый установщик, проверить состав вложенного исходного архива и запуск мастера.
