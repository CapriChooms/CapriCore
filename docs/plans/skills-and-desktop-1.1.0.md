# Capri 1.1.0 — план изменений навыков

Изменения затрагивают настольное приложение и отдельный репозиторий сайта. После каждого этапа проверяем затронутый интерфейс или контракт, затем запускаем проверку сочетаний и собираем локальный установщик. Конфигурация, личная память и реальные отчёты пользователей остаются вне сборки.

1. **Промпт по навыкам.** В `chat-service.mjs` разделить базовые правила и правила отдельных возможностей. В `main.mjs` собирать состояние только разрешённых навыков, в `desktopTurnContext` сериализовать только нужные поля. Применять один снимок настроек на весь ход, в том числе при повторной сборке после классификации. Правила безопасности и разрешения остаются на хосте. Проверить отсутствие Spotify, снимков и файлов в промпте после выключения, а также смену навыка между двумя запросами.
2. **Русский Qwen TTS.** Сопоставить на прогретом запуске `voice_queued` → `voice_synthesis` → `voice_audio`; внутри `qwen.py` измерять подготовку текста, авторегрессию и декодирование отдельно. Проверить текущие `cpuThreads`, dtype, ONNX для ударений и фактическое количество codec frames. Сравнить подходящие варианты на одном коротком и одном длинном тексте, с одинаковым сидом, сравнить длительность/разборчивость и пик RAM. Менять только подтверждённое узкое место, сохраняя CPU fallback и ударения.
3. **Размещение кнопок.** В `settings-catalog.mjs` и `main/skill-settings.mjs` добавить булево `composer` для reasoning, web search и attachments, с миграцией на прежние значения. В `skill-toolbar.mjs` раздельно применять `toolbar` и `composer` для основного и плавающего ввода. Верхняя кнопка вызывает общий обработчик, даже если её аналог в поле ввода скрыт. Проверить верх, ввод, оба, ни одного.
4. **Spoken replies.** В панели озвучки дать выбор Local/API и показывать настройки выбранного режима. Использовать существующие IPC `external-tts-*` и настройки модели, режим определять по `enabled` внешнего провайдера. Выключение внешнего режима сохраняет сохранённое подключение. Проверить выбор и отмену, загрузку моделей и отображение после перезапуска.
5. **Усилие рассуждения.** Валидируемое `low/medium/high` сохраняется в настройках reasoning. Передавать его только с активным Deep thinking. Адаптировать OpenAI Responses, OpenAI-compatible и локальный budget по возможностям, сохранить поведение для моделей без управления effort. Проверить исходящие тела запросов и локальные лимиты.
6. **Поиск.** Сохранить предпочтения поиска отдельно. Использовать существующий `WebSearch` и добавлять фиксированные адаптеры движков с ограниченными тайм-аутами. Фильтровать домены структурированно; пресеты источников — обычные наборы доменов. Сортировку по дате применять только если дата доступна, иначе сохранить порядок релевантности. Сохранять проверку URL и помечать данные из Интернета как внешние. Проверить формат запросов, фильтры и отсутствие тихой смены движка.
7. **Сохранённые факты.** Выделить пользовательские факты из технических файлов памяти, присвоить устойчивые ID, добавить редактирование, удаление и ручное добавление. Модель предлагает записи через отдельный структурированный путь, хост проверяет длину, дубликаты и отключение памяти. Удалённые факты не должны повторно попадать в контекст из старого индекса. Проверить миграцию, поиск, повторный запуск, удаление и приватный режим.
8. **Форматы вложений.** Общая таблица между `attachments.mjs` и Settings выводит формат, ограничения размера и наличие vision для текущего профиля. Не предлагать изображения и видео текстовой модели. Отдельно проверить Local, API без vision и API с vision.
9. **Цифры таймера.** В `time-panel.mjs` выделить существующие значения времени в визуальное колесо. Pointer capture, порог на один шаг, прокрутка колесом и стрелками, по желанию короткий существующий click SFX. Сохранить фокус, ручной набор и прежнее сохранение. Проверить границы, клавиатуру, touch и ПК с отключёнными анимациями.
10. **Screen Observation.** Использовать уменьшенный кадр в `screen-watch.mjs` для сравнения блоков и фильтрации локального движения. По смене foreground или крупному изменению сбрасывать ожидание, а на статике использовать максимум один содержательный кадр за минуту. Вызывать модель только на принятом кадре. Держать один активный анализ; отменять при выключении. Проверить статику, видео, переключение окон, несколько мониторов и связь с инициативой. Направление движения вычислять только если оно стабильно на последовательных кадрах.
11. **Доступ к приложениям.** Расширять каталог `desktop-catalog.mjs` через зарегистрированные Win32/MSIX и ярлыки Steam, сохраняя проверку владельца, одобрение и правила запуска. Системное обнаружение и запуск зарегистрированных приложений доступны с обычными правами Windows. Не превращать модель в административную оболочку. Проверить стандартное приложение, MSIX, переносной `.exe` и запрет чужого неподтверждённого приложения.
12. **Калькулятор на экране.** Добавить настройку Calculator. После вычисления внутренним калькулятором при включённой настройке открыть Windows Calculator через доверенный launcher и ввести только проверенное числовое выражение через UI API. Ошибка интерфейса не должна скрывать вычисленный результат. Проверить обычные и расширенные операции, фокус и выключенный режим.
13. **Слабая модель и локальные задачи.** Перед вызовом общего планировщика искать точное совпадение в доверенном каталоге приложений и игр. Для установленной Steam-игры использовать локальный ID и проверить запуск. Остальные планы ограничить повтором одного действия без изменения состояния, сохранить контроль пользователя и проверку результата каждого шага. Проверить ложные совпадения, явный запрос веб-поиска и отсутствие игры.
14. **Частота инициативы.** Поднять максимум до 120 в конфигурации, валидаторе и интерфейсе. Использовать прежние запреты во время разговора, сна и фокуса; не накапливать события, пропущенные под нагрузкой. Проверить 0, 120 и 121 и граничный интервал 30 секунд.
15. **Запись движения мыши.** Добавить версионированный тип траектории с координатами относительно исходного окна, ограниченными точками и временными смещениями. Упрощать точки при записи, проверять фокус и видимый индикатор при воспроизведении, сохранять Esc. Проверить отклонение опасных координат, отмену и старые workflow.
16. **User tools.** Оставить существующий отдельный переключатель разрешений. Добавить редактирование manifest/settings с повторным просмотром разрешений и безопасное удаление собственных каталогов с защитой от ссылок и одновременного запуска. Проверить активный процесс, невалидный manifest и повторное включение.
17. **Lava.top и обновления.** В `updates-panel.mjs` объяснить, что экспериментальные релизы закрытого `CapriChooms/Capri` предназначены для подписчиков Lava.top и требуют доступа на GitHub. Использовать фиксированную ссылку в `community-links.mjs`. Публичный стабильный канал остаётся доступен без подписки.
18. **История версий.** В updater добавить получение истории с репозиторием, тегом, признаком канала и ограниченным текстом release notes. Выбор загрузки привязать к проверенному asset и SHA-256. Показывать старые версии и объяснять, когда нужен отдельный каталог и полный установщик, чтобы не откатывать данные автоматически. Проверить старые, новые, одинаковые версии из двух источников и истёкший токен.
19. **Отправка багрепорта.** В приложении использовать уже очищенный ZIP из `diagnostics/report.mjs`; отправлять только при нажатии. На сайте отдельный Caddy reverse proxy к loopback-сервису рядом с существующими `deploy/*_release.py`: фиксированный предел запроса, rate limit, общий лимит диска, TTL, случайный ID, закрытый каталог. Просмотр через SSH администратора или отдельно авторизованный интерфейс без публичных URL вложений. Проверить синтетический отчёт, превышение размера, отказ чтения без доступа и конкурентные записи. Сверить деплой сайта и только после этого включать URL в сборке.
20. **Для разработчиков.** Дополнить существующий `diagnostics/developer.mjs` замерами по этапам и сводкой активных навыков. Оставить только обезличенные данные и технические метрики. Проверить отсутствие ключей и содержимого сообщений в экспорте.
21. **Сетка панели.** В `skill-toolbar.mjs` и CSS применить общую сетку без абсолютного позиционирования кнопок. Измерять высоту рядов через `ResizeObserver` с обновлением геометрии в одном кадре. Рамка должна располагаться ниже панели при любой ширине и DPI. Проверить все кнопки одновременно, компактный режим, 100%/150% и открытие/закрытие настроек.

Приёмка: тесты навыков и IPC, базовый чат с отключёнными и включёнными навыками, Local/API, обе поверхности ввода, экран и инициатива, уведомления обновлений с тестовыми данными, проверка файла установщика и его SHA-256. Пункты без реального измерения или стенда отмечаются отдельно.
