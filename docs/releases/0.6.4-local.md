# Capri 0.6.4 — local release candidate

This earlier candidate was superseded by the local 1.0.0 beta. Full conversation encryption was withdrawn before that beta; see [current test notes](1.0.0-beta-local.md).

## Changes to check

- Installer output retains split UTF-8 characters, separate output streams and the final unfinished line. Download/build progress should keep updating instead of losing messages.
- Explorer observation tolerates controls without a reported UI Automation type. Opening a folder and inspecting its controls should no longer crash the native helper.
- Calculator requests infer the calculator for the unambiguous calculation action when a model omits the application field. Explicit wrong targets and disabled permissions remain rejected.
- Computer planning recovers from the specific native PEG-format incompatibility with one JSON-mode inference retry. The host validates the complete action schema before accepting that plan; unrelated server failures do not trigger retries. See [reproduction and checks](../bugs/0.6.4-native-planner-json.md).
- Spotify waits briefly for its recognized search field to become accessible after restoration. It never substitutes an arbitrary text field or repeats text entry, and foreground checks remain enforced.
- Applying edited workflow steps preserves the workflow name entered in the editor.
- AMD/Intel resource monitoring uses native Windows counters instead of requiring NVIDIA tools. Missing usage retains confirmed GPU capacity, and the Local selector distinguishes measured CPU/GPU/mixed placement from an unloaded model. See [checks and limits](../bugs/0.6.4-amd-monitoring.md).
- Setup includes the separately pinned ROCm language-model backend on officially supported AMD configurations, with correct storage estimates and backend repair. Other Radeon cards retain the Vulkan route; voice support is checked separately. See [AMD runtime delivery](../bugs/0.6.4-amd-llm-runtime.md).
- Ordinary Windows companion, Settings and restore-chip windows use an explicit supported topmost level. This corrects an Electron 45 level-mapping failure while preserving the user's pin preference and temporary demotion during computer control.
- Local managed models reserve fewer output tokens for ordinary replies while retaining the larger Thinking budget. Stored context settings and provider choices are preserved.
- Popular-language settings have been proofread, including Russian voice preparation, memory, tray and microphone labels. All 50 interface catalogs and installer catalogs are checked for missing entries and mixed-script contamination.
- Logs and exported diagnostics omit raw dialogue, prompts, reference filenames and arbitrary child-process output.
- Reviewed compatibility-preserving security fixes are applied to the bundled glob and minimatch copies. Their upstream version numbers remain unchanged; audit tools may continue to flag those versions. See [the precise backport scope](../security-backports.md).
- Backend cleanup removes proven unused imports and avoids sorting GPU candidates during every memory estimate. The corresponding microbenchmarks are documented separately; they do not imply equivalent gains in model generation speed.

## Real verification and limits

Verification includes the installed production app, existing Discord and Explorer windows, installed local language/voice/recognition models, a real Brain document, a sandboxed user-tool process, and a saved API connection. Automated regression checks supplement these scenarios. The private qualification report records the exact tested scenarios and outstanding limits.

Discord minimize/restore interaction passed a cold production test on the development installation, including a native headpat and held-button drag. The earlier reported failure on another installation has not been reproduced; this candidate does not claim that report is conclusively fixed.

No test voice was broadcast into an active call. Tests on one computer do not establish compatibility with every GPU, microphone, game, provider or Windows installation.

The new issue #80 reports a native English speech-recognizer crash during model loading on 0.6.3 despite verified files. Its underlying cause remains unconfirmed; existing single-thread recovery is not evidence that the report is fixed. Follow-up should contain native exception/module metadata and package versions, without memory dumps or conversation contents.
