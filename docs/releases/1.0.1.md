# Capri 1.0.1 — local hotfix

- Support and bug-report links use the public **CapriChooms/CapriCore** repository; retained private-era community links migrate to the public destinations. **Report a bug** opens the public issue-form chooser.
- Removed the obsolete private-repository-access hint from the bug-report panel.
- Removed blanket BETA badges from established settings and their tray shortcuts. Experimental computer control, initiative, screen observation and model/backend warnings retain their labels.
- Fixed an API compatibility failure where a server returned an ordinary JSON completion for a streaming request. The proxy now converts that response to a valid stream without repeating the request; remote connection tests exercise streaming too.
- Prevented accidental selection of CPU/GPU/RAM/VRAM readings and interface labels, while keeping text editing and answer copying available.
- Diagnostic reports and a bounded technical log now include the selected model ID. Typed request failures retain their stage, status and safe network code; credentials and conversation content stay excluded. See [issue reproduction and checks](../bugs/1.0.1-public-issues.md).
- Includes the refreshed 1.0.0 documentation, roadmap and hardware/API guidance. Installer, desktop and updater metadata identify this build as **1.0.1**.

Run **CapriSetup-1.0.1.exe** and select the existing Capri installation folder to
upgrade while preserving settings, memory and downloaded models. Public updates
use CapriCore and do not require a GitHub account or token. Submitting a public
GitHub issue still requires signing in to GitHub.

This build is prepared locally for verification and is not published automatically.
