# Capri 1.0.2 — update recovery hotfix

- Fixed source updates deleting the installed desktop runtime. Version-only changes no longer reinstall unchanged npm dependencies. A required reinstall restores and checks the pinned Electron runtime before restart, including during recovery.
- Updates can be installed while the API or local core is offline. A disconnected core no longer produces the misleading “Wait for the current reply to finish” message. Actual replies and active installation operations still block restart.
- “Use local model” can download and prepare a first model from an API-only installation. An unconfigured API is no longer mistaken for an active local model; missing models remain repairable. Hardware restrictions and cancellation still apply.

If Capri cannot start after updating to 1.0.1, or its old updater is blocked, run
**CapriSetup-1.0.2.exe** and choose the **existing installation folder**. Keep the
folder and its data; an uninstall is unnecessary. The full installer repairs the
desktop while preserving conversation, memory, API settings and downloaded models.
Already installed 1.0.0/1.0.1 code cannot receive a fix before it opens the new installer.

The installer remains unsigned. Matching source, build manifest and checksums are
included. See [updates](../updates.md) for preservation and interrupted-update recovery.
