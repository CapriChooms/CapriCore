# Capri 1.0.3

- Faster local replies: fixed repeated model runner reloads and reduced unnecessary request preparation.
- Faster first voice startup. Saying “Capri” during active voice input no longer cuts off the beginning of the request.
- Fixed casual replies starting unrelated tool loops and interrupting speech. Personal-memory questions and requested actions keep their own tool access.
- Settings opens on the first click with animated loading placeholders while its content loads; temporary first-frame failures recover automatically.
- Language preferences are now in the first Capri category. The screen-observation control uses a capture icon matching the interface theme.
- Greetings no longer receive unrelated permission flags or action tools. Enabling Music animations now starts system-audio listening; diagnostics include detector and BPM status without recording audio.
- Choose CPU/GPU devices separately for the language model and voice. Settings → For developers shows request stages and first-audio timing without logging conversation contents.
- Clearer API setup: **API connections**, connection instructions, translated field examples, and a button to open local model storage, including Hugging Face downloads.
- Updated CapriCore logo colors and an installed-version label in Capri’s frame for easier bug reports.
- Installer reconnection tolerates brief control-file contention instead of failing immediately.
- Windows App Control launch blocks are reported as warnings after a successful installation, with a separate diagnostic code and an option to finish without retrying launch.
- Voice dependency downloads use bounded attempts and an official pinned PyTorch fallback. Setup shows the current package download instead of a stale Git check.

Run **CapriSetup-1.0.3.exe** and select your existing installation folder to keep
downloaded models, conversation, memory and personal settings. The installer
remains unsigned. Cold model loading and generation speed depend on the selected
models, devices and available memory; see the [latency measurements](../performance/first-token-latency.md).
