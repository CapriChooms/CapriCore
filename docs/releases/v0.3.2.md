# Capri v0.3.2

Installer recovery, voice setup and reliability fixes. This release collects the
locally tested fixes made after v0.3.1. Capri remains pre-alpha; numbered releases
do not imply that every hardware configuration has been qualified.

## Install or repair

Download **CapriSetup-0.3.2.exe** from Assets. Close Capri before updating, run the
new installer and select the **existing Capri installation folder**. Keep the
included English Capri voice selected if you want spoken replies. Complete setup
and restart Capri. Existing conversation, memory, settings and downloaded files
are preserved; verified cached components can be reused.

The setup includes the English Capri adapter/reference pack and the reviewed
character artwork. It downloads the required runtimes and selected base models.
No user recordings or voice training are required. Automatic spoken voice selects
the voice matching the conversation language; it does not install missing models.
Recognition and synthesis are separate components. Other supported spoken
languages need the optional multilingual speech models.

## Fixed

### Avatar and animation installation

- Source/setup release checks now require the reviewed runtime sprite catalog and
  all 68 referenced PNG frames. Installer preflight and final verification also
  validate the artwork, regardless of voice, recognition or model choices.
- Missing or damaged artwork keeps text chat available with a visible repair
  warning instead of silently substituting the geometric fallback. Repairing the
  existing folder with the full installer restores the bundled avatar.
- Diagnostic reports now include `avatar.json`: selected catalog, frame count,
  installed file sizes and missing-file information, without embedding images.

### English voice setup

- English voice availability now checks the adapter, reference, TTS model files
  and pinned download receipt, rather than assuming a Python executable and voice
  profile mean speech is installed.
- Languages marks an unavailable automatic voice as **Not installed** and offers
  **Download voice installer** for English. It directs users to the full setup
  with the included Capri voice, rather than a training script that cannot supply
  the character pack. Recovery instructions are available in English and Russian;
  other interface languages currently use English fallback for these new strings.
- An installation without the voice prerequisites shows a clear startup warning;
  trying to enable the absent voice no longer silently saves an ineffective choice.
- Multilingual setup retains its separate action. Spoken Voice intentionally has
  two choices: Automatic and Text replies only. Change Conversation language to
  select the corresponding supported spoken language.

### Cold startup and responses on smaller PCs

- PCs with up to 17 GiB reported physical RAM prepare the core, recognition and
  voice sequentially to reduce simultaneous loading/import memory peaks. Larger
  systems retain parallel startup, including after waking Capri.
- Context preparation and CPU request classification no longer consume the
  model's first-text timeout. They remain subject to the overall turn limit.
- Low-memory, minimal-profile and explicitly CPU-only setups allow up to 120
  seconds for first model text and 300 seconds for the whole turn. Other setups
  retain the 30/180-second limits. These are failure bounds, not added delays.
- Cold agent warmup on those slower setups can take up to 180 seconds; its
  technical request disables unnecessary thinking. Failed warmup is reported as
  a failed startup stage rather than a successful one.
- Response diagnostics record failure phase, elapsed time and timeout budgets
  without conversation text. Cancellation remains available; timed-out actions
  are never replayed automatically. Physical results on the reporting user's
  GTX 1660 Super still require user confirmation.

### Recovery after power interruption

- Fixed setup reopening with an invalid JSON primitive/constructor error when
  `ui-owner.json` or `ui-heartbeat.json` was damaged.
- Invalid UI control records are preserved as `.corrupt` copies and regenerated.
  Requests, target identity, installation journals and partial downloads are not
  reset. A recovered session stays paused until explicit continuation; a stopped
  worker can be retried through the wizard.
- PowerShell and native JSON writers flush temporary files before atomically
  replacing records. This reduces incomplete writes; it cannot guarantee disk
  hardware survives a power loss without data damage.

### False automatic pauses

- Resume now publishes a fresh heartbeat before clearing pause, under the same
  control lock as the worker guard. A stale guard observation cannot immediately
  undo the user's Resume action.
- Heartbeat age uses monotonic uptime, so Windows clock synchronization or manual
  clock changes do not invalidate a fresh UI pulse.
- Brief stale/unreadable heartbeat observations are confirmed before pausing.
  Default stale detection is 15 seconds plus 5 seconds of confirmation. Confirmed
  process exit or explicit window hiding still pauses immediately. Working in
  another application does not require keeping setup in the foreground.
- Busy control locks are retried instead of being treated as a lost window.
- UI event processing reads at most 128 lines per tick and appends console output
  in batches, keeping large package-manager/model logs from monopolizing the UI.
- Resume clears the obsolete automatic-pause notice. Genuine lost, hidden or
  unresponsive UI protection and explicit pause/cancel controls remain intact.

The v0.3.1 hidden-AppData Python bootstrap fix is included as well.

## Validation and limits

Regression coverage includes missing/damaged artwork, complete voice preflight,
slow preparation and bounded cancellation, low-memory startup ordering, native
Windows UI reattachment after corrupted control records, partial-download
preservation, stale-Resume/heartbeat/clock/lock races, bounded lossless event
reading, real pause/resume/cancel controls, and existing installer/update repairs.
The native installer payload and bundled voice pack are checked against their
manifests. GitHub CI must pass for the exact source commit before publication.

This is not a physical benchmark of every supported GPU. The installer remains
unsigned. Some reproduced failure modes were diagnosed from code and fixtures
because individual user attachments did not include the worker guard journal.
No private diagnostics, chat history, training datasets, credentials or local
machine configuration are included in the source release.
