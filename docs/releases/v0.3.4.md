# Capri v0.3.4

Pre-alpha maintenance release for installation, screen observation and desktop
reliability. Download **CapriSetup-0.3.4.exe** and select your existing Capri folder
to update/repair it. Personal conversation, memory, settings and downloaded models
are retained. Setup includes the reviewed sprite and English voice packs; optional
runtime/model downloads still require internet access and enough memory/disk space.

## Installation and downloads

- Nominal RAM reservations no longer reject a 32 GB PC reporting 31.4 GiB usable
  memory. The quality profile accepts at least 30 GiB usable RAM. Recommendation
  and acceptance now share the same bounded allowance in native setup and runtime;
  the detected RAM value is still shown unchanged. This is not a guarantee of free
  memory or GPU performance. See [issue #7](https://github.com/CapriChooms/Capri/issues/7).
- Temporary Ollama registry DNS/connection failures retry up to four times with
  2/4/8-second backoff through the same owned pull API. Verified/partial layers
  remain reusable. Pause/cancel are preserved; missing models and permanent
  failures stop normally. This hardens the failure shown in
  [issue #8](https://github.com/CapriChooms/Capri/issues/8); it cannot repair a blocked
  registry, offline connection or persistently broken DNS.
- npm recovery handles every unique lock-pinned failing tarball mentioned by npm,
  instead of only the first. Logs retain the transport failure code, partial byte
  count and final underlying cause. SHA-512, TLS, official registry, package pins
  and cache reuse remain. The source of the repeated connection resets in
  [issue #9](https://github.com/CapriChooms/Capri/issues/9) is not established; this
  release does not claim to repair the reporter's network connection.

## Screen observation and window movement

- Refreshing screen sources retains the explicit selection when that same live
  source and label are still present. It never selects another source as fallback.
- Observation stop requests are bound to their capture ID. A delayed stop from an
  old session cannot cancel its replacement. Cancelled one-shot capture is also
  released by ID instead of a broad cancellation during source changes. Hide and
  source disappearance still revoke access without silently resuming it. These
  changes address current state defects related to
  [issue #10](https://github.com/CapriChooms/Capri/issues/10).
- Dragging a transparent companion window preserves its dimensions in the same
  native operation as movement. A stationary held cursor no longer issues a move
  every 16 ms. Regression checks cover fractional-DPI size drift and repeated
  native window moves. A retest on the reporting PC is still useful for
  [issue #12](https://github.com/CapriChooms/Capri/issues/12).

## English speech compatibility

- English delivery instructions explicitly separate input recognition language
  from reply language. Russian recognition with an English conversation/voice
  remains a valid combination.
- Before English-only Turbo synthesis, substantial non-Latin reply text is rejected
  with an actionable language message; the normal text response remains available.
  Both the desktop queue and Python voice pool apply this cheap check. Accented
  Latin text, brief foreign proper names and multilingual speech remain accepted.
- This is a script mismatch guard, not a full language classifier or a guarantee
  against hallucinated audio from valid English. The exact cause of
  [issue #11](https://github.com/CapriChooms/Capri/issues/11) remains unconfirmed
  without diagnostics and an example response/recording. See
  [speech language compatibility](../speech-language-compatibility.md).

## Validation and existing reports

Local validation passed 354 Node tests, 33 Python tests, source/export/format
checks, native installer pages at 200% scaling, and isolated native observation
and window/dimming checks. Screen tests capture an owned generated fixture only;
no physical microphone, owner history or reporter hardware benchmark is implied.
The final source commit and release payload must pass CI and checksum verification
before publication.

All v0.3.3 fixes remain, including one-click setup diagnostics and the earlier
conversation/model-readiness corrections. Older reports #5 and #6 are being closed
as addressed by the accumulated released changes, without claiming a successful
physical retest. If a problem persists on v0.3.4, attach a fresh diagnostic ZIP to
an issue; setup has **Save report (ZIP)** and the app has the **!** report button.
