# Capri v0.3.5

Pre-alpha maintenance release for installation recovery and model downloads.
Download **CapriSetup-0.3.5.exe**, close any older setup window, and select your
existing Capri folder to update/repair it. Conversation, memory, settings and
downloaded models are retained. Setup includes the reviewed sprite and English
voice packs; optional runtime/model downloads still require internet access.

## Repairing interrupted installations

- Setup now checks that its private npm can load the dependencies needed by
  `npm ci`. A surviving `node.exe` and matching receipt can no longer hide a
  missing internal module such as `@sigstore/tuf/dist/appdata.js`. An incomplete
  bundle is restored from the checksum-verified Node archive. Identical files
  are retained during extraction, including an executable already in use.
  This addresses [issue #16](https://github.com/CapriChooms/Capri/issues/16).
- Ollama readiness now checks its required Windows CPU backend files, including
  `llama-server.exe`, instead of trusting the frontend executable alone. Setup
  repairs an incomplete bundle despite an otherwise valid receipt; runtime
  startup gives a specific repair message rather than a generic offline error.
- An interrupted managed Python environment is preserved under
  `.runtime/venv-recovery` before recreation. Healthy environments are reused.
  This applies to recognition, the CPU request router and voice setup; it does
  not clear model caches or user data. Together with the Ollama checks, it
  addresses the two failures confirmed in
  [issue #17](https://github.com/CapriChooms/Capri/issues/17).
- ZIP extraction handles directory entries with either path separator.

## More resilient downloads

- Recognized temporary network failures from uv now retry when uv returns exit
  code **2**, as seen in the reported PyTorch/torchaudio connection timeouts.
  Nested HTTP 408/429/5xx messages are recognized too. Permanent certificate,
  authentication, checksum, build and dependency-resolution errors still stop.
  The wrapper retains the same pinned command, official indexes and caches;
  ASR and request-router setup now use it as well. This fixes the missed retry in
  [issue #13](https://github.com/CapriChooms/Capri/issues/13) and the morning report.
  It cannot repair a persistent outage or blocked connection.
- After a specific Ollama registry TLS-handshake timeout, setup can try a bounded,
  certificate-verified compatibility probe using classical key exchange. Only a
  successful probe permits a saved per-install preference and a restart of
  Capri's idle, owned Ollama. TLS 1.3 remains available; certificate verification
  remains enabled. No global network settings are changed. See
  [model download compatibility](../models.md).
- Model pulls recognize nested transport errors and connection refusal. If the
  local service has exited, setup can start it again through the existing owned
  service path, then retry using Ollama's retained partial/verified layers. It
  never kills a living or foreign service. Retries remain bounded and cancellable.
- Final connection errors include useful transport codes. Setup diagnostic ZIPs
  now include bounded, redacted Ollama log tails. These changes improve recovery
  and diagnosis for [issue #18](https://github.com/CapriChooms/Capri/issues/18);
  the reason for that report's original stream interruption remains unconfirmed.

## Validation and remaining reports

Local validation passed **367 Node tests** and **34 Python tests**, including
native repair from a verified cached Node archive, offline Python-environment
recovery, diagnostic export, cancellation and owned-service recovery checks.
Source, export and formatting checks passed. The final Windows installer payload
is checked against the released source, all 68 sprite frames and the reviewed
English voice pack. Publication requires CI success for the exact source commit
and matching release-asset checksums.

No successful retest on the reporters' physical PCs is claimed. Issues
[#8](https://github.com/CapriChooms/Capri/issues/8),
[#11](https://github.com/CapriChooms/Capri/issues/11) and
[#18](https://github.com/CapriChooms/Capri/issues/18) remain open for diagnosis or
retesting. If a problem persists, attach a fresh ZIP using **Save report (ZIP)** in
setup or the **!** button in Capri. All v0.3.4 fixes remain included.
