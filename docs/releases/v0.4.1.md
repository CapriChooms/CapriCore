# Capri v0.4.1

This pre-alpha release improves screen-context reliability, permission confirmations, settings-window behavior, initiative and installation recovery. It also adds selective uninstall and default access to Capri's own files.

## Install or update

Download **CapriSetup-0.4.1.exe** from Assets and select your existing Capri installation folder to update. Close Capri and older setup windows first. Existing conversation history, settings, memory and downloaded models are retained.

The installer includes the English Capri voice adapter and sprites. Select the speech components you need in the wizard; the larger base models and runtimes still download during setup. **capri-en-v1.zip** is also provided separately for manual voice-pack import. It is not a replacement for the speech runtime and base model.

**Capri-0.4.1-source.zip** contains the reviewed source payload, not a preinstalled environment. Most users should choose the EXE. The installer remains unsigned. SHA-256 checksums are included in **SHA256SUMS.txt**.

## Default access to Capri's own installation

- Capri now receives read/write access to its entire installation folder by default, including source code, configuration, workspace, memory and application data.
- The installation folder appears in **Settings → File access**. You can turn off writing or revoke access completely. Revocation and read-only choices survive restarts; the default grant is migrated only once on existing installations.
- Existing additional folder grants are preserved. Other folders still need their own grants and initially remain read-only.
- Replacing or moving Capri's own files to the Recycle Bin no longer requires an extra confirmation dialog. Conflict detection, verified recovery copies and operation journals remain active. Additional folders retain their confirmation requirements.
- This intentionally enables self-modification: changes to application code or configuration can affect Capri when those files are loaded again. The file tools retain their documented size/type limits and do not provide a shell or binary model editor. See [File assistance](https://github.com/CapriChooms/Capri/blob/v0.4.1/docs/file-actions.md).

## Screen observation and incorrect responses

- Ordinary model turns now explicitly distinguish enabled observation from no current screen evidence. Expired scene descriptions are no longer forwarded as current observations.
- Historical one-shot images retain their provenance in structured metadata, without adding capture dates or source names to ordinary conversation text.
- Screen descriptions are explicitly independent of workspace/file permissions. A request such as “look at my screen” should use the current supplied scene or offer the real screen controls, not investigate workspace files.
- Corrected instructions that could lead a small model to invent `openclaw settings` commands, ask for tokens, search configuration files or create test files to enable screen observation.
- `settings_control` accepts an omitted value or `value: true` for a permission request. Both create a real approval request; neither directly starts capture.
- Pending approvals are explicitly reported as pending, not failed tool calls. The model is told to stop and wait instead of retrying through unrelated tools.
- **confirm**, **approve**, **подтверждаю** and **подтвердить** now work for a real, unexpired proposal that allows spoken/text confirmation. They cannot create a missing approval, replay a completed approval or bypass actions requiring physical buttons.
- Approving a screen request opens **Screen snapshot** settings. The owner still selects a window or monitor and presses **Start observation** before capture begins.

The supplied report showed a reply based on a day-old screen description; it did not establish a new capture without permission. These changes correct observed context and tool-flow defects. They do not guarantee that Qwen 2B will never produce an incorrect or repetitive answer. Existing conversation history is not silently cleared.

## Desktop applications and settings

- Fixed the application plugin failing to load from OpenClaw's temporary captured module graph. Its build helper no longer eagerly loads installation configuration from that temporary directory.
- Fixed blank/gray Settings windows appearing during shutdown, returning from the tray or delayed window loading. Settings are shown only after renderer readiness and an explicit open request, and are destroyed during exit/restart.
- The Qwen progress card is hidden when no operation is active. Actual preparation/download progress and actionable errors remain visible.

## Initiative

- **Occasional:** up to **10 comments per rolling hour**.
- **Conversational:** up to **30 comments per rolling hour**.
- Added a custom limit of **1–30 comments per hour**. An empty field uses the selected preset; changing presets clears the custom override.
- Scheduling and minimum spacing follow the selected limit. The complete rolling-hour budget is retained across restart.
- These are maximum rates, not guaranteed message counts. Quiet hours, user activity, fullscreen/excluded applications, ongoing speech and Capri's choice to stay silent still apply.
- New initiative and installation-access descriptions are included in all 50 supported interface languages.

## Private GitHub access and voice downloads

- The classic-token option and outside-collaborator guidance are visible before a failed access attempt.
- Fine-grained read-only tokens remain available for eligible organization members. Outside collaborators can use the documented classic-token path when the organization is unavailable as a fine-grained resource owner.
- Saved credentials retain the existing Windows-account encryption and validated GitHub download flow. A repository access failure does not mean that a separate paid voice license is required.

## Selective Windows uninstall

The uninstaller now provides independent checkboxes for:

1. Application files, dependencies and shortcuts — selected by default.
2. Downloaded models and imported voice packs.
3. Personal settings, conversation history, workspace, memory and permissions.

Unchecked groups are kept. Model/personal-data removal asks for a second confirmation. The graphical uninstall flow retains screenshots, original voice recordings and external files. Removing personal settings also removes local credentials. Unexpected filesystem links are rejected before file removal.

## Installation download recovery

- **[#29](https://github.com/CapriChooms/Capri/issues/29):** recognized Windows npm `ECONNRESET` exits reported as `-4077` or `4294963219`. These now enter the existing bounded retry/cache-recovery path rather than stopping immediately.
- **[#30](https://github.com/CapriChooms/Capri/issues/30):** recognized uv download interruptions containing Windows socket errors **10054**, **10053** or **10060**, including localized surrounding text. They now receive bounded retries using cached packages.
- Authentication, hash, dependency-resolution and unrelated process failures are not treated as transient network errors. Package pins, certificate verification and integrity checks remain intact.
- Production speech, voice and classifier installation already uses **uv**. `uv pip sync` is uv's compatibility subcommand, not a switch to the slower standalone pip installer.

The logs identify interrupted transfers, but cannot determine which server, ISP or intermediary reset the connection. This release fixes Capri's missed retry classifications; it cannot guarantee recovery from a persistent network block.

## Validation and remaining limits

- 444 automated Node tests passed before release preparation, including all eight selective-uninstall combinations, installation-access migration/revocation, conflict/recovery behavior, screen freshness and permission boundaries.
- 11 focused Python download-retry tests passed.
- Native Electron checks verified typed confirmation opening the screen picker without starting capture, installation-scope file replacement through the real Windows helper, custom initiative settings, hidden idle model progress and tray/settings lifecycle.
- Native token UI checks used a fixture credential; no real account permissions were changed.
- Installer extraction is checked against the source manifest, bundled voice profile, all 68 sprite frames and SHA-256 hashes. The published source commit is also checked by GitHub Actions.
- No new AMD/NPU TTS backend is included. Reported model-answer quality on the original user's Qwen 2B hardware has not been requalified in this release batch.

If a problem remains, attach a fresh **Save report (ZIP)** from setup or **! → Save report** from Capri immediately after the failure. Do not include access tokens in reports.
