# Capri v0.4.2

This pre-alpha maintenance release improves voice dependency downloads, Spotify activation, in-app update handoff, Settings window behavior, screen observation and model memory management.

## Install or update

Use **CapriSetup-0.4.2.exe** and select your existing Capri folder. Existing history, memory, settings and downloaded models are preserved. The installer includes Capri's sprites and English voice adapter; larger speech runtimes and base models still download during setup. **capri-en-v1.zip** remains available for manual voice-pack import and does not replace those dependencies. **Capri-0.4.2-source.zip** contains the source payload rather than an installed runtime.

If the older in-app updater cannot open its independent update window, run the new setup EXE directly and close the old Capri before applying it. Older installations cannot acquire the repaired updater until they are updated. Do not delete your existing models or personal data to retry.

The Windows installer remains unsigned. **SHA256SUMS.txt** contains checksums for the release assets.

## Compact view and window motion

- Redesigned signal core as a narrow mini-panel: up to 310 px wide with a 48 px procedural signal. Core and essential controls share a row; input and memory gauges remain available. Notifications and multiline drafts retain their space without overlapping controls. The backdrop follows the smaller visible area.
- Startup progress now occupies its own compact row between the toolbar and input instead of overlaying them with a full-width panel. The row disappears after startup. Native checks include simultaneous startup, notifications and multiline input at all three window sizes.
- Sleeping and disconnected Capri can now be collapsed or expanded manually. Sleep artwork appears on entry without repeatedly forcing the portrait open; expanding a sleeping portrait does not reload models. Waking respects the automatic reply expansion preference.
- Moved the portrait/compact toggle into the window-control group, immediately before hide-to-tray and quit. Settings remains directly accessible from compact mode.
- Added **Expand Capri when replying**, enabled by default, under **Appearance and animations → Portrait**. Turning it off keeps voice activation, streamed text, direct replies and speech in compact mode. Manual expansion and history access remain available; explicit reminder wake behavior is preserved.
- Added **Window motion** next to **Window dimming**: enable/disable, amplitude from 0 to 24 px, and a 4–30 second nominal cycle, with an animated preview. Motion is more noticeable by default, pauses during pointer interaction or text entry, respects reduced-motion settings and is bounded by available window space.
- New settings are translated into all 50 interface languages. Native checks cover compact layouts at 480×660, 380×480 and 320×360, expanded views, both reply preferences, direct and streamed replies, motion, reduced motion and saving settings.

## Community

- Added a Discord invite button to **Support the author**, alongside TikTok and GitHub, with a purple accent matching Capri's interface. It opens the official Capri community invitation in the browser. Existing community configurations inherit the new default link when it is missing.

## Memory monitor and Qwen loading

- Fixed premature first-reply timeouts on long conversations after startup or loss of Qwen's prompt cache. A bounded, read-only session metadata lookup now accounts for the existing context, even when the model weights are already resident. Large conversations can receive up to 150 seconds for the first text within the unchanged overall deadline; small conversations retain the normal watchdog. This does not make long-context inference faster. Cancellation, tool deadlines and no-replay behavior are preserved, and history is never cleared by this recovery.
- Added compact RAM/VRAM charts below the message input, enabled by default. Choose bars or rings, set the refresh interval to 3, 5 or 10 seconds, or disable them under **Settings → Appearance and animations → Memory monitor**.
- Charts show whole-system memory usage, including other applications. Hover for used/total GiB and the GPU name. With multiple GPUs, the card with the highest memory usage percentage is displayed rather than combining separate memory pools.
- GPU telemetry currently uses NVIDIA's driver utility. Unsupported or unavailable readings display a dash instead of a misleading zero. RAM works independently. Polling is bounded, shared between callers and suspended when the companion is hidden or the charts are disabled. All new settings labels are translated into the 50 supported interface languages.
- Desktop startup and wake prepare the enabled voice before loading Qwen, so Ollama sees its actual GPU memory allocation. The managed Ollama process reserves another 768 MiB per GPU for system headroom; if an enabled voice has not successfully loaded, another 3 GiB is reserved for a later voice start.
- Ollama still determines GPU offloading from available memory when loading models. The user's Qwen model and context size are preserved. Insufficient VRAM can result in CPU offloading and slower text generation; this policy does not promise equal speed on every GPU or recover memory already used by other applications.
- CPU-only Qwen preparation now explicitly honors the selected acceleration mode. Existing model caches are not rewritten merely to refresh a chart. Restart Capri to apply the new managed-service launch policy.

## Voice installation and interrupted downloads

- If PyTorch's `download-r2.pytorch.org` delivery route fails with a recognized transient network error, voice setup retries through the alternative official `download.pytorch.org` route.
- Both CUDA profiles retain their exact Torch/TorchAudio versions and pinned SHA-256 checksums. Package caches are preserved; retries are bounded. Certificate, authentication, checksum and dependency-resolution errors are not bypassed.
- Persistent failures now explain that successful ping does not establish HTTPS file-download access, and that browser-only VPN extensions do not cover the installer.
- Issue **#34** confirms connection resets and Windows socket error **10054** while downloading Torch/TorchAudio in v0.4.1. Its earlier dependency resolution, ASR and classifier steps succeeded. This is a network transfer failure, not evidence of a missing voice model or an incompatible GPU. The reporter states that VPN and zapret were disabled. The logs cannot identify whether the reset originated at the CDN, ISP, proxy or another intermediary.

Both official routes returned data during local verification, and the exact report activates the new fallback. This does not guarantee reachability from every user's network. No package, GPU-support or model version change is included.

## Spotify activation and confirmation dialogs

- Fixed the confirmation deadlock reported in **#31, #32 and #33**: enabling Spotify waited for a pending-settings-save barrier that was itself waiting for confirmation. The dialog no longer appears only after the request has expired.
- Expired, cancelled and completed confirmations are removed. Hidden Settings does not receive a duplicate confirmation intended for the companion.
- Draft saves still respect unsaved changes and revision checks. Spotify activation remains opt-in, preserves unrelated settings and rolls back configuration if restart fails.
- Speech-installation conflicts now identify the active installation rather than only reporting a generic busy state.

## Independent updater window

- The Windows update UI runs under its own windowed host and remains available when Capri exits to apply the update.
- Capri waits for the update window's readiness before shutdown; a failed launch leaves Capri running with the downloaded update available to retry.
- Updater UI and worker logs are retained and included in diagnostics. Successful handoff supports application restart after installation.

## Settings and tray lifecycle

- Removed the implicit native parent/child relationship that allowed Windows to restore Settings independently of Capri's requested UI state.
- Settings opens only after renderer initialization and its first paint. Hide/minimize, tray restoration, close, crash and shutdown follow one explicit lifecycle.
- Hidden windows are no longer repositioned on companion movement. Drafts remain available on a normal hide/reopen, and delayed callbacks cannot resurrect an obsolete Settings window.
- Native tests reproduced unintended owner-window restoration. The exact persistent gray appearance from every report was not reproduced; this fix does not assert a GPU-driver diagnosis.

## Screen observation and Capri's own avatar

- Added a shared visual reference for Capri's window, sprite and compact signal core. When the current evidence identifies her own interface, dialogue is instructed to use the first person. The reference does not assume she is present in every image.
- Current screen descriptions are distinguished from file access, historical screenshots and old approval messages. Description-only questions are instructed to use supplied evidence without requesting permissions again or investigating workspace files.
- Re-requesting already-active observation returns its enabled state without opening another picker or interrupting the selected source. Observation that is off still requires the owner's approval and explicit source selection.
- A single frame or IPC failure no longer immediately switches observation off. Bounded retries revalidate the same capture grant. Expiry, source closure, explicit stop, hiding Capri, screen lock and system suspension continue to revoke access.
- New diagnostic metadata records capture stop reasons and recent desktop tool outcomes without screenshots, scene descriptions, private argument bodies or credentials.

## Validation and remaining limits

- All 478 Node regression tests passed, including conversation prefill budgets and cancellation, manual sleep collapse, compact reply behavior, motion limits, shared memory sampling, unavailable counters, multiple GPUs, memory reserves, voice-first startup, preference migration and CPU-only preparation. The preceding Python qualification passed 45 tests; these interface changes do not modify Python code.
- Source syntax/dependency checks and repository-wide formatting checks passed.
- Native Windows checks passed for Spotify confirmations, Settings/tray/minimize behavior and the independent update window surviving parent exit and restarting the application.
- The native memory-monitor check exercises both chart styles and companion layouts, settings persistence and disabled/hidden polling in an isolated profile.
- The native observation check verifies fresh submitted frames, continued observation through a reply and revocation when hiding Capri or closing the selected source.
- Installer preparation verifies packaged source hashes, version metadata, the bundled English voice profile and all 68 sprite frames. Validation results are recorded alongside the prepared assets.

The network check reads bounded byte ranges rather than downloading multi-gigabyte Torch packages. Native UI tests use isolated profiles and controlled fixtures. Existing tests verify that voice URL checksums are enforced. Real Qwen answer quality on the reporter's hardware and a full multi-gigabyte clean installation are not requalified by these checks. No new AMD/NPU TTS backend is included.

If an error remains, save **Save report (ZIP)** in setup or **! → Save report** in Capri immediately after the failure. Review the archive before sharing and never include access tokens in an issue.
