# Быстрый режим беседы

Capri Desktop использует локальный классификатор перед Qwen. Для уверенно распознанной короткой английской беседы он отключает скрытое рассуждение на один ответ. Все сообщения с клавиатуры и из микрофона проходят через тот же ChatService, OpenClaw и общую сессию. Модель, персона, память, спрайты, инструменты и выбранный голос сохраняются.

Классификатор не выполняет команды и не генерирует ответы. Qwen получает исходные слова владельца без изменений и сама выбирает `spotify_control` и его аргументы. Быстрый режим не ограничивает инструменты и не создаёт отдельную историю.

## Установка и отключение

На этом ПК модель и отдельное CPU-окружение уже установлены. На новой установке запустите `setup-request-router.cmd`. Скрипт использует поставляемые проектом Python и uv, устанавливает зависимости из `config/router-requirements.lock.txt`, получает около 24 MB фиксированных файлов и проверяет модель и классификатор. Нормальный запуск приложения не обращается к сети за весами.

`config/request-router.json` управляет включением, числом CPU-потоков (4) и сроком ожидания классификации (150 мс). Для отключения установите `enabled: false` и перезапустите Capri. Если окружение, веса или классифицирующая голова отсутствуют, Capri продолжает обычную работу. Настройки озвучки и распознавания речи не меняются.

## Модель и выбор режима

Используется фиксированный `sentence-transformers/all-MiniLM-L6-v2`, ONNX INT8 AVX2, CPUExecutionProvider. Отдельная бинарная логистическая голова обучена на 176 написанных для проекта английских примерах. Encoder заморожен: это MiniLM с обученной головой, не полный цикл дообучения SetFit. Для калибровки выделены 28 других примеров, для проверки — ещё 52. История владельца и аудио при обучении не использовались.

Голова и 32 опорных вектора поставляются в `config/request-router-head.json`. Семантическое сходство проверяет, что запрос находится достаточно близко к знакомой обычной беседе. Порог оценки головы 0,85 и минимальное сходство 0,50 выбраны до проверки отдельного тестового набора. Оценки не следует интерпретировать как калиброванные вероятности правильной маршрутизации.

Запрос сохраняет обычный режим, если он слишком длинный, содержит неанглийские буквы, числа, код, признаки задач, музыки, памяти или ссылку на предыдущий контекст. Короткие ответы после команды тоже сохраняют обычный режим. Эти консервативные проверки ничего не исполняют: они только запрещают ускорение. Например, смешанная просьба “Tell me something cheerful and save it in my notes” идёт к Qwen с рассуждением.

Фразы “the other one”, “do that again”, “same as yesterday” не получают быстрого режима. Классификатору передаются максимум две последние пользовательские реплики, по 400 символов, только для обнаружения короткого продолжения задачи. Это вспомогательный ограниченный контекст; настоящий диалог и память остаются у OpenClaw.

На отдельном наборе из 52 фраз ускорены 8 из 16 обычных реплик; все 36 защищённых, смешанных и неоднозначных фраз сохранили обычную обработку. Старые 42 исследовательских примера дополнительно проверены на отсутствие ускорения защищённых запросов. Наборы небольшие и синтетические, поэтому эти результаты не гарантируют безошибочную работу на произвольных запросах. Выбран консервативный охват; обычная беседа тоже может остаться в полном режиме.

## Передача режима и устойчивость

Постоянный Python-процесс загружается параллельно с ядром. Он использует только CPU, не загружает Torch/голосовые веса и общается с главным процессом Electron через закрытые stdin/stdout. Дополнительного HTTP-сервера нет. В среду процесса не передаются ключ Gateway и токены внешних сервисов. Входные сообщения не записываются в журналы классификатора.

Пока процесс прогревается, при ошибке, переполнении, невалидном ответе или превышении 150 мс выбирается обычный путь. Зависший процесс завершается; следующие сообщения не повторяют ожидание его запуска. Перезапуск приложения заново готовит классификатор. При отмене реплики отменяется ожидание классификации, поздний результат игнорируется, запрос к Qwen не отправляется. Выход из приложения освобождает дочерний процесс.

Для быстрого запроса ChatService добавляет `x-capri-thinking-once: off`. Проверенное исправление закреплённого OpenClaw принимает его только после аутентификации и авторизации, только для владельца агента Capri, и передаёт штатный `thinkingOnce: off`. Оно не использует постоянный `thinking` или `sessions.patch`. Следующий обычный запрос получает текущие настройки общей сессии. Неизвестные значения заголовка отклоняются. Запросы без заголовка сохраняют прежнее поведение.

Изменения OpenClaw закреплены версией и SHA-256 в `integrations/openclaw-compat/patches.json`. При новой версии зависимости нужен обзор исправлений. Настройка `thinkingDefault: low` и лимит рассуждения 64 сохранены. Простого добавления `reasoning_effort` в старый HTTP-запрос недостаточно; исправление передаёт режим через поддерживаемый внутренний параметр.

## Проверки и воспроизведение

```powershell
node --test tests/*.test.mjs
.\.runtime\router-venv\Scripts\python.exe -m unittest discover -s tests -p request_router_test.py -v
.\.runtime\router-venv\Scripts\python.exe scripts/verify-request-router.py
node scripts/verify-desktop.mjs --routing
node scripts/verify-request-routing.mjs
```

Последний скрипт использует настоящую Qwen и выбранный голос в удаляемых тестовых сессиях. Он проверяет быстрый и обычный режимы в одном контексте, отсутствие сохранённого изменения `thinkingLevel`, реальный read-only вызов Spotify, первый текст и готовность первого аудиофрагмента. Состояние воспроизведения не меняется. Контрольная сумма рабочей истории сравнивается до и после. Задержки включают работу моделей и могут заметно зависеть от холодного системного префикса и конкуренции за GPU; это небольшая проверочная серия, а не SLA. Первое аудио измеряется до Web Audio и аудиодрайвера.

Отчёты: `logs/request-router-verification.json`, `logs/request-routing-integration.json`, `logs/desktop-verification-latest.json`. Модели и журналы исключены из Git. В renderer отправляется только служебное событие `turn.routing` с выбранным режимом и длительностью; оно не попадает в текст ответа и озвучку.

Сквозная проверка 26 октября прошла: последовательность fast → normal → normal → fast дала соответственно 0 → ненулевое → ненулевое → 0 символов скрытого рассуждения, а сохранённый уровень сессии остался low. Qwen вызвала только read-only `spotify_control: status`, рабочая история совпала. Классификация обычных реплик заняла 2,3–3,9 мс. В прогретой паре вопроса о тихом вечере первый текст ускорился с 4,874 до 4,306 секунды, готовность первого аудио — с 8,152 до 8,018 секунды. Первая пара после перезапуска Gateway включала дорогую первичную обработку префикса (19,952 секунды до текста в baseline), поэтому среднее всей серии нельзя приписывать классификатору. Реальное ускорение начала голоса зависит также от длины первой фразы и синтеза.

Повторное обучение головы: `scripts/train-request-router.py`, CPU-среда `.runtime/router-venv/`. Для этого отдельного developer workflow установите `scikit-learn==1.9.1` в эту среду через `uv pip install --python .runtime/router-venv/Scripts/python.exe scikit-learn==1.9.1`, затем запустите её Python со скриптом обучения. Обычной работе sklearn не нужен; повторный setup синхронизирует только рабочий lock-файл. Корпус: `config/request-router-corpus.json`; независимые регрессии: `tests/fixtures/request-routing.json`. После изменения корпуса нужны калибровка и проверка качества.

Исходная модель: [MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), Apache-2.0; при установке записывается атрибуция рядом с файлами. Точная ревизия, размеры и SHA-256 весов и токенизатора находятся в `config/request-router-upstream.json`. Исторические экспериментальные прототипы удалены; рабочий классификатор и независимый проверочный корпус сохранены.
