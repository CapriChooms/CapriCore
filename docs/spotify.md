# Spotify в Capri

Capri управляет уже установленным и авторизованным настольным Spotify для Windows через инструмент OpenClaw `spotify_control`. Текст и распознанная речь проходят через одну беседу и используют один инструмент. Исходники включены в дистрибутив, но на чистой установке доступ выключен. Микрофон включается отдельно.

## Команды

Обращайтесь к Capri обычными фразами на выбранном языке общения. Примеры на английском:

- “Play I Really Want to Stay at Your House by Rosa Walton.”
- “Pause Spotify.” / “Resume Spotify.”
- “Next song.” / “Previous song.”
- “Set Spotify volume to 25 percent.” / “Make Spotify quieter.”
- “Mute Spotify.” / “Unmute Spotify.”
- “Skip to one minute into the song.”
- “Enable shuffle.” / “Repeat this track.” / “Turn repeat off.”
- “What is playing on Spotify?”
- “Add Never Fade Away by SAMURAI to the queue.”
- “What is next in the queue?” / “Show my Spotify library.”
- “Play my Liked Songs.”

Можно передать ссылку `https://open.spotify.com/track/…` или `spotify:track:…`. Для поиска учитываются названия и исполнители. Отдельный поиск возвращает до восьми настоящих кандидатов; выбор `resultId` сохраняет конкретную версию. Результаты действуют десять минут и обновляются после изменения страницы. Для альбомов, исполнителей и плейлистов есть категории поиска. Доступность отдельных действий зависит от версии клиента и аккаунта; основной проверенный сценарий — песни, управление воспроизведением и очередь.

Громкость — уровень приложения Spotify в микшере Windows. Голос Capri, общая громкость компьютера и другие программы не меняются. Ползунок внутри самого Spotify остаётся независимым: итоговая громкость зависит от обоих уровней. Если Spotify ещё не создавал звуковую сессию Windows, один раз запустите в нём песню.

## Установка на другом компьютере

Требуются Windows 10/11 x64, .NET Framework 4.x из Windows, установленный Spotify с выполненным входом и рабочее ядро Capri. Отдельные Spotify OAuth-токены, ключи приложения и пароль не нужны.

1. Откройте **Меню → Доступ к приложениям → Spotify** (английский интерфейс: **Menu → Application access → Spotify**).
2. Нажмите **Включить Spotify** и подтвердите перезапуск. Capri соберёт локальный модуль, остановит своё ядро, добавит только разрешение Spotify и перезапустится. История, память, выбранная Qwen, параметры генерации и прочие разрешения сохраняются. Резервная копия конфигурации остаётся в приватной `data/config-backups/`.
3. Откройте настольный Spotify и войдите в аккаунт. Нажмите **Проверить подключение** в том же разделе. Проверка только читает состояние и не меняет музыку.
4. Попросите Capri включить музыку. **Отключить Spotify** отзывает доступ после перезапуска. Если файлы локального модуля отсутствуют или устарели, доступна кнопка **Восстановить Spotify**; отключение по-прежнему возможно.

Альтернатива для командной строки: остановите Capri и её локальное ядро, выполните `setup-spotify.cmd` из корня проекта, затем запустите Capri заново. Не запускайте CLI-настройку одновременно с работающим ядром. Открытие меню и просмотр статуса сами по себе не предоставляют доступ.

Компилятор Windows используется локально. Сборка помещается в `.runtime/spotify-bridge/<hash>/`; исходники проверяются по SHA-256 перед запуском. После изменения C# выполните установку повторно. Уже запущенный плагин подхватит новую собранную версию при следующей команде.

## Как это устроено

`integrations/spotify/index.mjs` регистрирует узкий инструмент. `service.mjs` проверяет аргументы, последовательно выполняет команды и связывает повторный идентификатор вызова с тем же результатом. Неоднозначно завершившиеся операции автоматически не повторяются.

Все музыкальные запросы поступают в Qwen вместе с текущим контекстом беседы. Модель сама определяет намерение, выбирает действие и аргументы `spotify_control`, получает фактический результат и формулирует ответ. Оболочка не распознаёт команды по шаблонам и не выполняет их до обращения к модели. Это относится и к короткой паузе, и к свободным формулировкам вроде просьбы сделать музыку тише. Новое пользовательское сообщение один раз поступает в общую сессию; история не пересылается повторно.

После простой команды Capri получает указание подтвердить результат одним коротким предложением без встречного вопроса или дополнительных реплик. Например: “Spotify volume is now 25%.” Инструмент возвращает относящиеся к действию поля и готовое фактическое `confirmation` для обычных настроек громкости, паузы, звука и режимов. В ответе также отмечено, что снимок состояния истекает при следующем сообщении пользователя. Новая проверка громкости требует нового чтения `status`, даже сразу после изменения. Текст не обрезается принудительно после генерации.

Для выбора действий используется рассуждение с ограничением 64 токена; после инструмента — быстрый проход без повторного рассуждения. При полностью отключённом планировании Qwen3.5-9B в проверках иногда отвечала подтверждением без вызова инструмента. Родной шаблон модели и исправления доставки описаны в [performance.md](performance.md). Рассуждение не показывается в субтитрах и не озвучивается. Spotify-плагину не предоставляется доступ к сырой переписке через хуки.

Отдельный C#-процесс обменивается с плагином JSON через закрытый stdin/stdout. Он использует Windows Media Controls для медиаинформации и части настроек, Core Audio для громкости только процессов Spotify и UI Automation для настоящих элементов клиента. Состояние проигрывателя уточняется по его панели, поскольку Windows может обновлять метаданные с задержкой. Запуск выбранной песни проверяется по названию, исполнителю и признаку воспроизведения.

Поиск и меню иногда временно выводят Spotify на передний план. Текст вводится только после проверки фокуса его поля поиска; координаты меню вычисляются из найденного элемента и проверяются на принадлежность окну Spotify. Произвольные клавиши, координаты, программы и адреса модель передать не может. Фокус и курсор возвращаются, если пользователь не успел переключиться сам. Если окно перекрыто или Windows запрещает фокус, Capri сообщает об ошибке и просит вывести Spotify вперёд.

Для ссылок используется официальный публичный [oEmbed](https://developer.spotify.com/documentation/embeds/reference/oembed) только для получения названия ресурса. Запрос идёт к фиксированному адресу Spotify без авторизации и cookies, с ограничением времени и размера ответа. HTML из ответа не исполняется. Поиск и обычные команды не обращаются к этому endpoint.

## Границы

- Работает с настольным клиентом на этом компьютере. Другие устройства Spotify Connect и веб-плеер в браузере не управляются.
- Очередь и медиатека возвращают доступную в интерфейсе часть списка, до 40 и 80 элементов соответственно. Это не полный экспорт аккаунта.
- Редактирование облачных плейлистов, управление подпиской и аккаунтом не реализованы.
- Реклама, недоступный контент и ограничения аккаунта сохраняются. Интеграция не обходит их. Проверка проведена на Spotify Free; Premium не является условием этого локального способа.
- Селекторы рассчитаны прежде всего на английский клиент. Для ряда элементов предусмотрены русские названия; полное покрытие других языков не проверено. Изменения интерфейса Spotify могут потребовать обновления селекторов.
- Cookies и Spotify-токены не читаются. Новый сетевой порт не открывается. Метаданные музыки считаются данными, а не инструкциями для модели.

Spotify Web API — отдельный возможный адаптер для облачных возможностей. Его [управление воспроизведением](https://developer.spotify.com/documentation/web-api/reference/start-a-users-playback) требует Premium, а [правила development mode](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) ограничивают приложения и пользователей. Текущая реализация использует клиент, в который пользователь вошёл самостоятельно.

## Проверка

`spotify.cmd status` и `npm run verify:spotify` только читают состояние. `spotify.cmd search "title artist"`, `spotify.cmd play "title artist"`, `spotify.cmd pause`, `spotify.cmd volume 25`, `spotify.cmd queue` вызывают тот же инструмент, что и Capri.

`node tools/verify/verify-spotify.mjs --controls --search` временно проверяет громкость, звук, паузу, перемотку и режимы, затем восстанавливает их. Для проверки реального запуска и очереди добавьте `--playback --restore-uri spotify:track:ID_ТЕКУЩЕЙ_ПЕСНИ`. Название ссылки сверяется с исходной песней до изменения музыки. Этот расширенный тест меняет контекст воспроизведения; исходная песня, позиция и настройки восстанавливаются, прежняя автоматически составленная очередь не восстанавливается.

`node tools/verify/verify-spotify-dialogue.mjs` проверяет свободные формулировки, относительную громкость, продолжение по контексту, запрос без изменения музыки и внешнее изменение воспроизведения. Для каждой реплики проверяются состояние Spotify и настоящий вызов инструмента именно моделью в истории OpenClaw; для простых команд — одно предложение до 24 слов без встречного вопроса. Проверочная беседа удаляется через API OpenClaw; основная история не меняется. Результаты находятся в игнорируемой Git папке `logs/`. Общие тесты: `npm test`.

Для проверки запуска песни именно фразой из диалога у этого скрипта также есть `--playback --restore-uri spotify:track:ID_ТЕКУЩЕЙ_ПЕСНИ`. Он проверяет полный путь команды, реальное воспроизведение и ответ локальной модели, затем восстанавливает исходную песню и настройки.

Можно использовать только `--playback`: тогда скрипт заранее находит исходную версию песни для восстановления и останавливается до изменений, если не может её однозначно определить. `--thinking off` или `--thinking low` меняет режим только временной проверочной беседы для сравнения.

## Tool timing and request budget

A named playback request should use one Qwen-selected `play(query)` call. The bridge already searches and verifies playback, so a separate search/model/play cycle is unnecessary unless the owner asks to browse results. Desktop requests opt in to run-scoped tool lifecycle metadata. A real start receives up to 45 seconds for execution; its matching result grants a fresh 30-second final-answer window. The absolute 180-second request limit remains, and keepalives or repeated call IDs cannot extend a stalled action. The footer displays Working with Spotify while the tool runs. Uncertain actions are never replayed automatically.

The Capri desktop prompt uses the native compact surface, deduplicates only an exactly repeated SOUL body, and sizes the local model's reserve to its existing 2048-token output limit. Tool permissions, persona files, shared history and memory are preserved; the model and 16384-token context do not change. Run `node tools/verify/verify-spotify-timeouts.mjs` for a real read-only Spotify/Gateway check and a non-executed Qwen `play(query)` selection test. Its report is `logs/spotify-timeout-verification.json`.
