# Capri: voice activation and feedback

Enable the microphone with its button. It starts off at app launch and uses the previously selected input device. With capture enabled, Capri waits locally for “Capri” or “Hey, Capri”. Say the address and the request together, or pause briefly after the address and then give the request. The wake address is removed before sending the prompt into the shared conversation. One address opens one prompt; the gate rearms after that prompt. An unused window closes after ten seconds. Typed messages work as before.

While waiting, the interface shows “SAY CAPRI”. Ordinary room speech is not displayed as a draft, sent to Qwen, stored in chat, or allowed to interrupt Capri. The microphone and local ASR must still process audio to detect the address. Capture stays memory-only and turning the microphone off releases it. Existing behavior while hidden in the tray is unchanged: capture can remain enabled. This feature is not speaker verification and can react to someone else or a recording that says a sufficiently similar address.

The same accurate Parakeet recognizer checks up to three short audio prefixes while waiting for the address (default interval: 0.8 seconds of speech). No second speech model or draft text is used. Prefix text stays internal to wake matching and never reaches the UI or conversation. Final utterance recognition is independent and takes priority. A bounded phonetic matcher accepts common name variants such as "Capree", "Cabrie", "Cappy", "cat free", "hay capree", "hey cap free" and Cyrillic transcriptions. A bare name must start an address; an embedded mention such as "I visited Capri" is ignored. Less certain candidates get a 120 ms hold. The full final transcript provides a fallback when an early name check fails. The recognized wake prefix also provides word times. The complete utterance is decoded with its full acoustic context, then address words are removed by their time interval rather than by spelling alone. This handles a confirmed Capri later rendered as Copy without treating Copy as a global wake alias. Legitimate copy/leave requests are preserved. The already-cleaned result is marked so the gate cannot remove the command's first word a second time. Detection never calls Qwen. Accuracy and timing depend on pronunciation, noise and CPU load; this is not speaker identification.

The match immediately reveals the character from signal core and keeps that attention through the next voice turn. It also plays a soft, rising two-tone confirmation (about 230 ms), flashes the portrait frame and shows an “I'M LISTENING / SPEAK NOW” badge. The microphone button changes from waiting yellow to listening cyan and the badge bars follow actual microphone level. The badge remains while the command window is open, then disappears. If a request was already completed in the same breath, a brief “HEARD YOU / REQUEST RECEIVED” acknowledgement replaces it; turning the microphone off clears feedback immediately. Reduced-motion mode retains the static visual confirmation without the pulse.

The default signal is generated by Web Audio on the already-unlocked microphone context: no speech model, audio download, file or extra inference is involved. Settings → Microphone also offers a custom file, cached Capri voice or silence. Applying a voice choice prepares the phrase in the selected speech language; the microphone reloads it when preparation completes. The cache is bound to the phrase, language and voice, and an unavailable cache does not substitute the signal. Recognition continues during the cue. Acknowledgement works independently of muted automatic voice replies and is routed to the system output; the visual confirmation remains usable if that output is muted or unavailable. When interruption is enabled, only addressed speech interrupts playback. Echo rejection remains active. If the address is spoken alone, it does not create a greeting/model turn; Capri waits for the actual request. “Stop listening” / “microphone off” still disable capture without requiring an address. Stop buttons also remain available.

`config/companion-asr.json` contains `wakeWord.enabled`, `commandWindowMs` and `ambiguityHoldMs`. Disabling the gate explicitly restores continuous command input. The existing continuous-ASR verification uses that disabled configuration in an isolated verification process; production ignores its test override. Recognition stays on CPU. Speech activity extends the open command window during longer requests, without generating word drafts.

Checks:

```powershell
node --test tests/wake-phrase.test.mjs tests/wake-feedback.test.mjs tests/microphone.test.mjs
node scripts/verify-wake-phrase.mjs
# Optional compatibility check for the two-word address:
node scripts/verify-wake-phrase.mjs --hey
```

The real-ASR test uses an isolated desktop, a generated bare “Capri” (or “Hey, Capri” with --hey) and a public speech fixture through Electron's fake microphone. It verifies that speech before the address is ignored, the core expands promptly, the listening badge and cue are scheduled, and exactly one accurate prompt enters the fake Gateway without the address. An OfflineAudioContext render checks that the procedural cue produces finite, bounded PCM and ends promptly. Physical output is muted in automation. It neither records a physical microphone nor calls Qwen. The direct-Parakeet two-word-address fixture measured 98 ms after the generated clip ended on this PC. Current measured timing is recorded per run in the report; a single synthetic fixture is not a microphone-independent latency guarantee. Private report: `logs/wake-phrase-verification.json`.
